# Frontend handoff — 2.5 Build leases and cancellation

Backend-only delivery. The build queue is now a durable lease-based
scheduler with owner-epoch fencing, cooperative cancellation, attempt
history, concurrency caps, and operator drain/pause controls. No console
UI was added or changed.

## Backend delivered

- `build_runs` carries the lease: `owner_epoch`, `lease_expires_at`,
  `attempt_count/limit`, `cancel_requested_at/by`, `deadline_at`,
  `last_heartbeat_at`. Claim, heartbeat, and completion are
  compare-and-swaps on `(builder_id, owner_epoch)`; a superseded owner
  gets `ErrBuildLeaseLost` and must drop the work.
- `build_attempts` records every claim (`leased/succeeded/failed_terminal/
  worker_lost/cancelled/timed_out/superseded`).
- `builder_workers` tracks liveness plus a `drained` flag;
  `build_scheduler_control` holds the queue-wide `paused` flag.
- Cancelling a queued build finishes it immediately. Cancelling a running
  build sets `cancel_requested_at` and transitions the deployment; the
  late builder completion then converges the build to `cancelled` without
  publishing an image or scheduling a rollout.
- Worker loss (lease expiry) requeues with bounded retries; retry
  exhaustion, build timeout, and maximum queue age are terminal.
  Caps: global and per-project concurrent builds (projects stand in for
  workspaces until 3.1). Fairness/quotas stay in 3.19/3.3.
- Builder wire: `BuildJob` carries `lease_epoch`, `lease_expires_at`,
  `deadline_at`; heartbeat, log report, and completion present
  `lease_epoch` and are fenced on it.

## Deferred UI

1. Build status surfaces should show lease/cancellation progress:
   `attempt_count/limit`, owning `builder_id`, and a "cancelling" state
   while `cancel_requested_at` is set on a `running` build.
2. An attempt-history view per build (worker loss, takeover, timeout).
3. An operator build-queue surface: running/queued counts, per-builder
   current build and drain toggle, queue pause/resume. Until the 3.10
   operator control room lands, this view has no home and stays unbuilt.

## API contracts (backend)

`PlatformService` (`api/proto/platform.proto`):

- `BuildStatus` gains `attempt_count`, `attempt_limit`, `builder_id`,
  `lease_expires_at`, `cancel_requested_at`.
- `ListBuildAttempts(ListBuildAttemptsRequest{service_id, build_id})`
  returns `BuildAttempt{attempt_number, builder_id, owner_epoch,
  started_at, finished_at, outcome, detail}` oldest first. Service-read
  authorized; cross-service `build_id` is rejected.

`OpsService` (operator-only; non-operators get `PermissionDenied`):

- `ListBuilders(google.protobuf.Empty)` returns
  `BuilderWorker{id, name, current_build_id, last_heartbeat_at, drained,
  updated_at}`.
- `SetBuilderDrain(SetBuilderDrainRequest{builder_id, drained})` —
  drained builders finish running work but take no new claims; resuming
  their own running build still works. Unknown builder is `NotFound`.
- `GetBuildScheduler(google.protobuf.Empty)` returns
  `BuildSchedulerState{paused, running_builds, queued_builds,
  max_concurrent_global, max_concurrent_per_project, updated_at}`.
- `SetBuildSchedulerPaused(SetBuildSchedulerPausedRequest{paused})` —
  paused queue takes no new claims; running work finishes.

Go (`internal/controlplane/delivery`): `ClaimNextBuild`,
`HeartbeatBuild` (`ErrBuildLeaseLost` / `ErrBuildCancelled`),
`CompleteBuild` (epoch-fenced, converges cancelled/superseded late
completions), `RecoverExpiredBuilds`, `BuildAttempts`, `ListBuilders`,
`SetBuilderDrain`, `BuildSchedulerState`, `SetBuildSchedulerPaused`,
`BuildSchedulerConfig`/`WithDefaults`. Connect wrappers exist in
`internal/controlplane/connect_services.go`.

## Acceptance criteria

- Cancelling a running build shows "cancelling" until the build reaches
  `cancelled`; the late image never becomes the service's resolved image.
- Attempt history shows each claim with builder, epoch window, outcome,
  and detail.
- Draining a builder (or pausing the queue) stops new claims within one
  claim round while running builds complete; undrain/resume restarts
  claims; counts in `BuildSchedulerState` match the queue.
- Non-operator callers cannot list/drain builders or pause the queue.
