# Frontend handoff — 2.6 Deploy-by-digest

What runs is now `artifact.image_ref`, which is pinned by digest. A tag is user input only and never the running identity.

## Build

1. Wherever a deployed or running image is shown (service panel, deployment history, build status), show `artifact.image_ref` from `DeploymentRecord.artifact` / `BuildStatus.artifact`. Show a tag only as the input it came from, e.g. `nginx:latest → nginx@sha256:…` using `source_image_ref`. Rollback and redeploy confirmations show the digest that will run.
2. Deployments with `reason_code = BUILD_REUSED` did no build. Show them as "reusing image built for commit …", with no empty build progress.

## Rules

- Direct-image resolution errors (private registry not allowlisted, auth required, redirect refused) already arrive as actionable deploy errors; render them as they are.

`ListServiceArtifacts` exists, but a provenance view is not needed for MVP.
