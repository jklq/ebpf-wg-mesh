# Frontend handoff — 2.3b Dashboard secret rotation

The backend rotates signing keys through the `controlplane signing-keys` CLI (runbook: `docs/signing-keys.md`). The dashboard needs one change so that rotating `dashboard-session` does not log everyone out.

## Build

1. Add an optional `DASHBOARD_JWT_SECRET_PREVIOUS`, loaded with the same rules as `DASHBOARD_JWT_SECRET`. Refuse to start when it equals the active secret. Verify tokens against the active secret, then the previous one; always sign with the active secret.
2. Document both rotations in the dashboard runbook: session (31-day overlap, then clear `_PREVIOUS`) and user assertion (swap `DASHBOARD_CONTROLPLANE_USER_ASSERTION_SECRET`; the control plane accepts both for 5 minutes, so no dashboard verification change is needed). The distinctness checks must pass for the *new* pair.

There is no key-management UI or RPC, and none is wanted.
