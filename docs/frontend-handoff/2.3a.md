# Frontend handoff — 2.3a Sealed secrets

This is the console half of [1.2](../todo/01-running-service.md#12-sealed-secrets-in-the-console). The backend is complete.

## Build

1. On the service variables screen, add a **sealed secrets** section next to public variables. It lists `ListServiceSecrets` (name, version, updated time), offers write-only create/update via `SealServiceSecret` (never pre-fill the value), and deletes via `DeleteServiceSecret` with confirmation.
2. On deployment detail, label `sealedVersions` as the pinned secret versions; rollback restores them. Never show values.

## Rules

- Follow the existing `*FromSession` → server-fn pattern. The zod name rule mirrors the backend: `[A-Za-z_][A-Za-z0-9_]*`, 1–128 characters, `PLATFORM_` reserved. The value limit is 64 KiB.
- Names are disjoint from public variables. Show the backend `FailedPrecondition` message and tell the user to remove one side.
- A value travels from the input field to the RPC and nowhere else: not into loader data, logs, toasts, or test snapshots.
- A duplicated environment copies zero sealed secrets. That is intended.
