# Frontend handoff — 2.9 Durable bounded logs

Backend-only delivery. The log path is now a durable bounded pipeline:
agents and builders spool output to disk, ship with stable line
identities, every shed line surfaces as an explicit read gap, and reads
are paginated with tenant retention enforcement. No console UI was
added or changed.

## Backend delivered

- The five log types (runtime, build, deploy, http, network) are
  preserved end to end. Raw lines are retained byte-exact up to the
  documented 64 KiB per-line limit (`logpipeline.MaxLogLineBytes`);
  longer lines keep the exact prefix and set `truncated`. The pipeline
  never parses customer output.
- Structured attributes and event names exist only on lines the
  platform emitted (`build.started`, `build.finished`,
  `deploy.started`, `allocation.crash_loop`). Customer output lines
  carry none.
- Ordering is `(observed_at, line_id)`. `line_id` is a stable
  producer-assigned identity, so at-least-once delivery with reconnect
  replay deduplicates server-side instead of duplicating rows.
- Agents and builders have bounded disk-backed spools with batching,
  retry with backoff, backpressure, and per-key drop counters. A
  ClickHouse outage costs disk space and latency, never unbounded
  memory, and never blocks workload reconciliation.
- Per-allocation/per-build rate and burst limits on producers plus a
  per-allocation ingest guard in the control plane. Every shed window
  (rate limiting, spool overflow, ingest shedding) is persisted as a
  `ServiceLogGap` row with a bounded reason code.
- Tenant retention: `projects.log_retention_days` (1..90, 0 = platform
  default) is applied as the per-row ClickHouse TTL for both lines and
  gap rows. Project deletion GC purges the project's rows after the
  grace period; TTL expiry is the backstop.

## Deferred UI

1. Log viewers must page lines with the opaque cursor and gaps with
   the gap cursor instead of assuming one response holds the range,
   and must render gap rows as explicit
   "N lines dropped (reason)" markers in the timeline rather than
   silently omitting the window.
2. Truncated lines should render a truncation affordance (for example
   a "line truncated at 64 KiB" note).
3. Structured platform events should be visually distinct from raw
   output and expose their attributes (outcome, reason, digest, target
   agents) — e.g. as a details affordance on the line.
4. A per-project log retention control (days, 1..90, or "platform
   default") calling `UpdateProjectLogRetention`, showing the effective
   retention on the project settings surface.

## API contracts (backend)

`PlatformService` (`api/proto/platform.proto`):

- `ListServiceLogsRequest` gains `page_token` (opaque forward cursor
  from a previous response; empty starts at `start_time`; lines return
  oldest first) and `gap_page_token` (opaque forward gap cursor; empty
  starts at `start_time`; gaps return oldest first by window).
  `ListServiceLogsResponse` gains `next_page_token` (empty when the
  range is exhausted), `gaps`, and `next_gap_page_token` (empty when
  the gap range is exhausted). Lines and gaps paginate independently.
- `ServiceLogLine` gains `attributes` (map, platform events only),
  `truncated` (bool), `event` (string, empty for plain output), and
  `line_id` (stable identity; also the pagination tiebreaker).
- `ServiceLogGap{allocation_id, build_id, log_type, stream,
  dropped_count, reason, window_start, window_end}` marks a window
  where lines were dropped. `reason` is one of `rate_limited`,
  `spool_overflow`, `ingest_overflow`, `corrupt_spool`. Gaps overlap
  the queried time range and are returned alongside lines, capped at
  500 rows per page with `next_gap_page_token` for continuation.
- `Project` gains `log_retention_days` (0 = platform default).
- `UpdateProjectLogRetention(UpdateProjectLogRetentionRequest{
  project_id, log_retention_days})` returns the updated `Project`.
  Write-authorized on the project; `log_retention_days` is 0 or 1..90
  (`InvalidArgument` otherwise), and deleted projects return
  `FailedPrecondition`.

Regenerate console clients with `bun run generate:proto`; all changes
are additive.

## Acceptance criteria

- Log views fetch pages via `next_page_token` until exhausted and do
  not duplicate or skip lines across pages when new lines arrive
  (forward-only cursor).
- A window with a gap renders the gap marker with the dropped count and
  reason between the surrounding lines at `window_start`/`window_end`.
- Lines over 64 KiB render the retained prefix with a truncation
  notice, and platform-event lines render event name and attributes
  without pretending they are customer output.
- Project settings show the effective log retention and can set/reset
  it within 1..90 days; out-of-range input surfaces `InvalidArgument`
  without losing user input.
- Tenant isolation holds in the UI: a member of project B never sees
  project A lines or gaps through any log surface.
