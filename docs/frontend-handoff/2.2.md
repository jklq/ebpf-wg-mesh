# Frontend handoff — 2.2 Source object storage

Backend-only change. No console UI work is required for this item.

## What landed

Production source snapshots moved from a shared control-plane filesystem
directory to content-addressed immutable objects in operator-provided
S3-compatible storage. The filesystem provider remains for local development
and is rejected in production. No protobuf, API, or console-visible behavior
changed: builds, source summaries, and the builder snapshot download stream
work exactly as before.

## Observable contracts (no UI to build)

- Health readiness keeps the `source_storage` check: it fails when the
  configured archive backend is unavailable, for both providers.
- Builder snapshot download failures now distinguish causes in gRPC status
  codes and build failure text: `NotFound` (snapshot row or object missing),
  `DataLoss` (digest/size verification failed), `Unavailable` (storage
  backend temporarily unavailable, safe to retry). Console already renders
  build failure strings; no change needed.
- Startup contract logs `source_storage=durable|loopback|ephemeral|unset`
  based on the configured provider. No credentials appear in the contract,
  logs, or error strings.

## Acceptance criteria

- [ ] No console change ships for 2.2; existing service/build/source views
      behave identically against file and S3 backends.
- [ ] A build whose snapshot object is missing or corrupt surfaces the
      failure text from the builder (already implemented, no UI work).
- [ ] If a future operator console (3.10) shows dependency health, it can
      read the existing readiness report; nothing new to expose.

## Deferred

Nothing. There is no deferred UI for this item.
